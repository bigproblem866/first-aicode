# ERP系统开发环境设计文档

## 文档说明

本文档面向 ERP 系统**开发阶段**的架构设计与环境搭建规范，聚焦「本地能跑、快速开发、结构清晰」三个目标，不涉及商用级高可用、分库分表、多租户等复杂设计，适合项目初期 MVP 阶段使用。技术栈为 **Vue3 + Spring Boot + MyBatis-Plus + Spring Cloud Alibaba**。

---

## 一、开发环境整体规划

### 1. 环境分层

开发阶段只需维护两套环境即可：

| 环境 | 用途 | 部署方式 | 数据 |
|------|------|----------|------|
| Local | 本地开发调试 | 本机直接运行 | 造测试数据 |
| Dev | 团队联调共用 | 一台开发服务器 Docker Compose | 共享测试数据 |

> UAT、生产环境等项目后期再搭建，开发阶段不投入精力。

### 2. 开发环境技术清单

| 类别 | 选型 | 说明 |
|------|------|------|
| JDK | JDK 17 | Spring Boot 3.x 最低要求 |
| 构建工具 | Maven 3.8+ | 后端依赖管理 |
| Node.js | 18.x LTS | 前端构建 |
| 数据库 | MySQL 8.0 | 本地 Docker 或本机安装 |
| 缓存 | Redis 7.x | 本地 Docker 或本机安装 |
| 注册配置中心 | Nacos 2.x | 本地 Docker 单节点即可 |
| 消息队列 | RocketMQ 5.x | 本地 Docker 单节点（可选，初期可不用） |
| 容器 | Docker Desktop | 一键启动中间件 |
| IDE | IntelliJ IDEA / VS Code | 后端 IDEA，前端 VS Code |

## 二、后端项目结构（Maven 多模块）

开发阶段采用「模块化单体 + 微服务预留」的结构，所有业务在一个工程里，后期需要拆分时平滑过渡。

### 1. 整体目录

```
erp-cloud                          # 父工程（根目录）
├── pom.xml                        # 统一版本管理
│
├── erp-common                     # 公共模块
│   ├── erp-common-core            # 返回结果、异常、工具类、常量
│   ├── erp-common-mybatis         # MyBatis-Plus 配置、分页、自动填充
│   ├── erp-common-redis           # Redis 工具类
│   └── erp-common-security        # JWT 工具、登录上下文
│
├── erp-gateway                    # 网关（开发阶段也必须有，统一入口）
│   └── src/main/java/com/erp/gateway
│       ├── config                 # 跨域、路由配置
│       └── filter                 # 登录鉴权过滤器
│
├── erp-system                     # 系统管理服务（用户、角色、菜单、字典）
├── erp-mdm                        # 主数据服务（物料、客户、供应商）
├── erp-purchase                   # 采购管理服务
├── erp-inventory                  # 库存管理服务
├── erp-sales                      # 销售管理服务
├── erp-finance                    # 财务管理服务
└── erp-auth                       # 认证授权服务（登录、Token）
```

> 开发初期如果觉得服务太多启动慢，可以先只开 `erp-auth`、`erp-system`、`erp-gateway` 三个，其他业务服务按需启动。

### 2. 单个业务服务内部结构（以 erp-inventory 为例）

```
erp-inventory
├── pom.xml
└── src
    ├── main
    │   ├── java/com/erp/inventory
    │   │   ├── InventoryApplication.java    # 启动类
    │   │   ├── controller                    # 接口层
    │   │   ├── service                      # 业务层
    │   │   │   └── impl
    │   │   ├── mapper                       # DAO 层
    │   │   ├── entity                       # 数据库实体
    │   │   ├── dto                          # 入参对象
    │   │   └── vo                           # 返回对象
    │   └── resources
    │       ├── mapper/                      # MyBatis XML（复杂 SQL 写这里）
    │       └── bootstrap.yml               # 服务配置
    └── test                                 # 单元测试（可选）
```

### 3. 端口规划

| 服务 | 端口 |
|------|------|
| erp-gateway | 8080 |
| erp-auth | 8081 |
| erp-system | 8082 |
| erp-mdm | 8083 |
| erp-purchase | 8084 |
| erp-inventory | 8085 |
| erp-sales | 8086 |
| erp-finance | 8087 |

| MySQL | 3306 |
| Redis | 6379 |

### 4. 核心配置示例

**bootstrap.yml（每个服务通用，只需改 application name）：**

```yaml
server:
  port: 8085

spring:
  application:
    name: erp-inventory
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848
      config:
        server-addr: 127.0.0.1:8848
        file-extension: yml
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://127.0.0.1:3306/erp_inventory?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: root
    password: root
  data:
    redis:
      host: 127.0.0.1
      port: 6379
```

**网关路由配置（application.yml）：**

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: erp-auth
          uri: lb://erp-auth
          predicates:
            - Path=/api/auth/**
        - id: erp-system
          uri: lb://erp-system
          predicates:
            - Path=/api/system/**
        - id: erp-inventory
          uri: lb://erp-inventory
          predicates:
            - Path=/api/inventory/**
```

### 2. Vite 配置（开发环境）

```javascript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import path from 'path'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, 'src')
    }
  },
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',  // 网关地址
        changeOrigin: true
      }
    }
  }
})
```

### 3. Axios 封装（utils/request.js）

```javascript
import axios from 'axios'
import { ElMessage } from 'element-plus'

const service = axios.create({
  baseURL: '/api',
  timeout: 10000
})

// 请求拦截：自动带 Token
service.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers['Authorization'] = 'Bearer ' + token
  }
  return config
})

// 响应拦截：统一错误处理
service.interceptors.response.use(
  response => {
    const res = response.data
    if (res.code !== 200) {
      ElMessage.error(res.msg || '请求失败')
      return Promise.reject(new Error(res.msg))
    }
    return res.data
  },
  error => {
    ElMessage.error(error.message)
    return Promise.reject(error)
  }
)

export default service
```

## 四、本地中间件一键启动（Docker Compose）

在项目根目录创建 `docker-compose.yml`，一条命令启动所有中间件：

```yaml
version: '3.8'

services:
  mysql:
    image: mysql:8.0
    container_name: erp-mysql
    environment:
      MYSQL_ROOT_PASSWORD: root
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql

  redis:
    image: redis:7-alpine
    container_name: erp-redis
    ports:
      - "6379:6379"

  nacos:
    image: nacos/nacos-server:v2.3.0
    container_name: erp-nacos
    environment:
      MODE: standalone
    ports:
      - "8848:8848"
      - "9848:9848"

volumes:
  mysql-data:
```

启动命令：

```bash
docker-compose up -d
```

> 开发阶段 RocketMQ 可以先不启动，等需要做异步消息时再加。

## 五、开发启动顺序

按以下顺序启动本地服务，避免启动报错：

1. **启动中间件**：`docker-compose up -d`，确认 Nacos 控制台能访问（http://localhost:8848/nacos，默认账号 nacos/nacos）
2. **初始化数据库**：创建 `erp_system`、`erp_mdm`、`erp_inventory` 等数据库，执行建表 SQL
3. **启动 erp-gateway**：网关启动后才能统一访问后端接口
4. **启动 erp-auth**：登录认证服务
5. **启动 erp-system**：系统管理服务
6. **启动前端**：`npm run dev`，访问 http://localhost:3000
7. **其他业务服务**：开发哪个模块就启动哪个，不用全部启动

## 六、开发阶段不做的事情

为了快速推进业务开发，以下内容**开发阶段不投入精力**，等项目稳定后再补充：

- 分库分表、读写分离
- 服务多副本、负载均衡集群
- 多租户隔离
- 分布式事务 Seata（初期用本地事务 + 简单 MQ 即可）
- CI/CD 自动化流水线
- 监控告警、链路追踪（用 IDEA Debug + 日志足够）
- 复杂的权限体系（先做菜单 + 按钮权限，数据权限后期再加）
- 异地容灾、数据备份策略

## 七、数据库初始化规范

### 1. 库规划

开发阶段每个服务一个库，方便后期拆分：

| 数据库名 | 所属服务 | 核心表 |
|----------|----------|--------|
| erp_system | erp-system | sys_user、sys_role、sys_menu、sys_dept、sys_dict |
| erp_mdm | erp-mdm | mdm_material、mdm_customer、mdm_supplier |
| erp_purchase | erp-purchase | pur_order、pur_order_detail、pur_receipt |
| erp_inventory | erp-inventory | inv_stock、inv_stock_log、inv_check |
| erp_sales | erp-sales | sal_order、sal_order_detail、sal_delivery |
| erp_finance | erp-finance | fin_receivable、fin_payable、fin_voucher |

### 2. 建表规范

所有表必须包含以下基础字段：

```sql
CREATE TABLE 表名 (
    id            BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    create_by     VARCHAR(50)  DEFAULT NULL COMMENT '创建人',
    create_time   DATETIME     DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_by     VARCHAR(50)  DEFAULT NULL COMMENT '更新人',
    update_time   DATETIME     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    is_deleted    TINYINT      DEFAULT 0 COMMENT '逻辑删除：0正常 1删除',
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='表注释';
```

## 八、开发规范简版

### 1. 后端规范

- 接口路径统一 `/api/模块名/功能`，例如 `/api/system/user/list`
- 返回格式统一：`{ code: 200, msg: "成功", data: {} }`
- Controller 只做参数校验和调用 Service，不写业务逻辑
- MyBatis XML 只写复杂联表查询，单表 CRUD 用 MyBatis-Plus 内置方法
- 跨服务调用必须用 OpenFeign，禁止直接读其他服务的库

### 2. 前端规范

- 页面文件统一叫 `index.vue`，放在以功能命名的目录下
- 接口按模块统一写在 `src/api/` 对应文件里，不在组件里直接写 axios
- 表格查询、表单弹窗这些通用模式封装成公共组件复用
- 字典下拉统一用 `<dict-select type="xxx" />`，不每个页面手写
